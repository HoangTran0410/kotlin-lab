# M2 — UI tối thiểu chạy thông suốt (bản nháp)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Một app React nơi user gõ Kotlin, thấy graph coroutine tự sinh, và **tua timeline được hai chiều**. Console in `println` theo thời gian ảo, DiagnosticsPanel báo lỗi theo dòng, LessonNav mở ba lesson có sẵn.

**Architecture:** `runSourceSafe(src) → { diagnostics, events }`. Trace là nguồn sự thật duy nhất: mọi thứ hiển thị tại step N đều là `foldTrace(events, N)`. Hình dạng graph (`buildGraphSpec`) suy từ **toàn bộ** trace nên bất biến theo step; ELK chạy đúng một lần cho mỗi lần compile; scrub chỉ đổi *diện mạo* node, không bao giờ đổi *vị trí*.

**Tech Stack:** React 19, Vite 5, `@xyflow/react` 12, elkjs 0.12, CodeMirror 6, Zustand 5, Vitest 2.1 (giữ nguyên), Playwright cho một smoke test.

## Phát hiện tiền đề — ĐỌC TRƯỚC KHI LẬP LỊCH

Bốn điều dưới đây đo được trên code M1 tại `20420e5`. Chúng đổi hình dạng của M2, nên ghi ở đây thay vì để lộ ra giữa lúc thực thi.

### P1. `runSource` NÉM khi source chưa gõ xong — chặn toàn bộ editor sống

Đã đo (`runSource` gọi trực tiếp, không try/catch):

```
''                                    OK    diag=1  "Không tìm thấy fun main()"
'fun main() = runBlocking {'          THROW ParseError: Mong đợi RBRACE nhưng gặp 'EOF'
'fun main() = runBlocking {\n  launch { del'
                                      THROW ParseError: Mong đợi RBRACE nhưng gặp 'EOF'
'fun main() { println("abc }'         THROW Error: Lexer: chuỗi chưa được đóng, dòng 1, cột 22
'!!!???'                              THROW ParseError: Không phân tích được biểu thức...
'fun main() = runBlocking { val c = Channel<Int>() }'
                                      OK    diag=1  (validator, có line/col)
```

Trong một editor sống, source **chưa gõ xong ở gần như mọi phím**. Nếu UI gọi thẳng `runSource`, app sẽ trắng màn hình liên tục. `Diagnostic[]` chỉ được trả về từ *validator* — lỗi *lexer* và *parser* đi bằng đường ném.

Thêm nữa: `ParseError` có mang `pos: Pos` (dùng được), nhưng lexer ném **`Error` trần**, vị trí chỉ nằm trong chuỗi thông điệp — DiagnosticsPanel không có số dòng để nhảy tới. → **Task 2**.

### P2. `srcLine` gần như rỗng — tính năng highlight dòng CHƯA CÓ DỮ LIỆU

Đo trên cả ba lesson: **2/159 event** có `srcLine`. Cả hai đều là `PRINTLN` của lesson `supervisor`.

```
jobtree      srcLine on 0/51
normalfail   srcLine on 0/44
supervisor   srcLine on 2/64
```

Nguyên nhân: trong toàn engine chỉ **một** call site truyền `srcLine` — `Scheduler.println` (`scheduler.ts:66`). Khoảng 25 lời gọi `emit()` còn lại bỏ trống tham số.

Thiết kế §6 ghi `CodeEditor` "tự highlight dòng đang chạy theo `srcLine`". Với dữ liệu hiện tại, dòng highlight sẽ đứng im suốt trace rồi nhảy một cái ở `println`. **Tính năng chính của editor không có gì để chạy.**

Tin tốt: mọi node AST đều đã mang `pos: Pos` (`ast/nodes.ts`), và interpreter đã có `e.pos.line` ngay tại chỗ (`interpreter.ts:332` dùng đúng nó cho `println`). Nên đây là công việc **luồn tham số**, không phải công việc thiết kế lại. → **Task 3**.

### P3. `src/lessons/index.ts` dùng `node:fs` — không bundle được cho browser

```ts
import { readFileSync } from 'node:fs'
export function loadLessonSource(id: string): string {
  return readFileSync(join(here, id, 'main.kt'), 'utf8')
}
```

Vite sẽ vỡ khi build cho browser. Golden test của M1 đang phụ thuộc module này nên **không được sửa tại chỗ** — phải thêm một registry song song. → **Task 5**.

### P4. `foldTrace` RẺ — không cần cơ chế tăng dần

Đo trên máy này (Node 20.19.0), `foldTrace` gập **toàn bộ** trace một lần:

| trace | số event | `foldTrace(full)` một lần |
|---|---|---|
| ba lesson M1 | 44 – 64 | 0.0014 – 0.006 ms |
| `repeat(200)` sinh ra | 3 211 | 0.26 ms |
| `repeat(1000)` sinh ra | 16 011 | **0.49 ms** |

Một khung hình 60fps có 16.7 ms. Gập lại từ đầu ở **mỗi tick kéo** tốn 3% một khung hình, trên một trace lớn hơn bất cứ bài học nào chúng ta định viết 250 lần. **Không cần snapshot, không cần fold tăng dần, không cần cấu trúc dữ liệu bền.** Chi tiết ở §"Quyết định 1".

Cảnh báo cái bẫy: gập tại *mọi* step (`for n in 0..N`) là O(N²) và tốn 3.9 giây ở 16k event. Đó là hình dạng của một **test**, không phải hình dạng của thao tác kéo. Đừng nhìn con số đó rồi kết luận nhầm là scrub chậm.

## Quyết định 1 — Hình dạng quản lý state

**Kết luận: giữ đúng như thiết kế §6. Zustand chỉ giữ `stepIndex`, `WorldState` tính bằng selector có memo hoá. Không cần sửa gì.** Đo đạc ở P4 xác nhận, không phải phỏng đoán.

Store giữ **ba** thứ, và chỉ ba:

| Trong store | Vì sao |
|---|---|
| `source: string` | Input thật của user. Không suy ra được từ đâu. |
| `compiled: { events, diagnostics, spec }` | Kết quả của một hàm thuần trên `source`. Nằm trong store vì compile theo nhịp gõ phím (debounce), không nằm trong render. |
| `stepIndex: number` | Con trỏ của user trên timeline. Không suy ra được. |

Mọi thứ khác — `WorldState`, danh sách node/edge, dòng console, dòng đang highlight, marker timeline — là **hàm thuần của ba thứ trên**. Không cái nào được phép sống trong `useState`.

**Vì sao không dùng snapshot/fold tăng dần dù nó "rõ ràng nhanh hơn":**

1. Không cần: 0.49 ms trên trace lớn gấp 250 lần thực tế (P4).
2. Fold tăng dần đòi state khả biến vượt qua giữa các tick. Đó chính là "mô hình state song song" mà ràng buộc cấm — và là thứ *sẽ* trôi lệch khi kéo lùi.
3. `WorldState` chứa `Map` khả biến. Chia sẻ một snapshot giữa các step là mời gọi đúng lớp lỗi mà M1 đã tốn một vòng review để bắt (Task 8: hoist `WorldState` ra module scope làm test suy biến thành `x === x`). Chúng ta trả 0.49 ms để mua lại tính thuần khiết đó.

**Memo hoá vẫn cần**, nhưng vì lý do khác — không phải vì fold đắt, mà vì `foldTrace` trả **object mới mỗi lần gọi**, nên nếu gọi thẳng trong selector thì mọi component sẽ re-render ở mọi lần store đổi, kể cả khi `stepIndex` không đổi. Memo hoá theo khoá `(events, stepIndex)` biến nó thành ổn định về tham chiếu.

**Rào chắn hồi quy** (Task 6): một test khẳng định `foldTrace(full)` dưới 5 ms trên trace 16k event, và một test đếm số lần `foldTrace` thực sự chạy khi `stepIndex` không đổi phải bằng 0. Nếu về sau ai đó làm `foldTrace` thành O(N²) hoặc phá memo, test đỏ ngay chứ không đợi user thấy giật.

## Quyết định 2 — Graph không được rung khi tua

Đây là vấn đề UI khó nhất của M2. Trả lời tường minh.

### Nguồn gốc của rung

Cách làm ngây thơ là: mỗi step, lấy `foldTrace(events, n).jobs`, đưa vào ELK, vẽ. Cách này **hỏng chắc chắn**, vì tập node lớn dần theo step: ở step 8 có 3 job, step 9 có 4. ELK layered nhận đồ thị khác thì trả toạ độ khác — mọi node đã có sẽ nhảy chỗ khi một node mới sinh ra. Kéo qua 60 step là 60 lần bố cục nhảy. Không dùng được.

### Cách sửa: tách **hình dạng** khỏi **trạng thái**

Quan sát then chốt: `foldTrace` **chỉ thêm job, không bao giờ xoá** (`w.jobs.set(...)`, không có `delete`). Nên tập node là **đơn điệu tăng**, và tập node tại step cuối là **hợp** của mọi tập node ở mọi step.

Vậy thì:

- **Hình dạng** (`GraphSpec`: có những node nào, cha con ra sao, có những cạnh nào) suy từ **toàn bộ `events`**, không phải từ `foldTrace(events, n)`. Nó **không phụ thuộc `n`**. → Task 4, hàm thuần trong engine.
- **Trạng thái** (Active/Cancelled/…, đang chạy trên thread nào, đang suspend vì gì) suy từ `foldTrace(events, n)`. Nó phụ thuộc `n`, nhưng chỉ đổi *màu, viền, nhãn, độ mờ* — **không bao giờ đổi `position`**.

ELK chạy **đúng một lần cho mỗi lần compile**, không phải một lần mỗi step. Kéo scrubber không hề gọi tới ELK. Đây không phải tối ưu hoá — đây là điều làm cho việc kéo *đúng đắn*.

### Node chưa sinh ra thì hiện thế nào

Vị trí đã được giữ chỗ sẵn từ đầu. Ba lựa chọn, chọn (b):

- (a) Ẩn hẳn (`hidden: true`) → để lại lỗ trống không giải thích được, trông như bug.
- (b) **Bóng mờ: viền đứt nét, opacity 0.18, không nhãn.** Người học thấy "sẽ có gì đó ở đây" mà chưa bị lộ tên/loại. Chọn cái này.
- (c) Vẽ đầy đủ nhưng nhạt → lộ trước toàn bộ cấu trúc, mất phần "bung ra dần" vốn là nội dung bài học.

### Bốn nguồn rung còn lại, mỗi cái một cách chặn

1. **Kích thước node đo từ DOM.** ELK cần `width`/`height` *trước* khi bố cục. Nếu lấy kích thước bằng cách đo text đã render, ta có vòng lặp đo→bố cục→đo và bố cục nhảy một khung hình sau mỗi lần render. → **Kích thước cố định theo kind**, khai báo thành hằng số (`NODE_W = 200`, `NODE_H = 68`). Nhãn dài thì cắt bằng CSS `text-overflow`. Task 11.
2. **Toạ độ con của compound node.** ELK trả toạ độ con **tương đối với cha**; React Flow v12 cũng đặt node có `parentId` **tương đối với góc trên-trái của cha** (đã xác minh trong tài liệu React Flow: *"Child nodes are positioned relative to the parent's top-left corner"*). Hai bên khớp nhau, **không được cộng dồn offset của cha** — cộng vào là con văng ra ngoài hộp. Task 12 có một test khoá đúng điều này.
3. **Thứ tự mảng `nodes`.** React Flow đòi **node cha phải đứng trước con** trong mảng, nếu không quan hệ cha-con xử lý sai. `buildGraphSpec` phải phát node theo thứ tự BFS/thứ tự tạo (job cha luôn có `seq` của `COROUTINE_CREATED` nhỏ hơn con, vì con chưa tồn tại khi cha chưa sinh). Task 4 khẳng định bất biến này bằng test.
4. **ELK bất định do thứ tự input.** ELK layered deterministic khi đồ thị vào giống nhau, nhưng "giống nhau" tính cả thứ tự mảng. `buildGraphSpec` sắp theo `seq`, không duyệt `Map`. Task 11 test: chạy `layoutGraph` hai lần trên cùng spec cho toạ độ y hệt.

### Compound node là gì

Quy tắc đồng nhất: **node là container khi và chỉ khi nó có ≥1 con trong cây cấu trúc.** Không cần liệt kê builder. `coroutineScope`/`supervisorScope`/`runBlocking` bọc con là chuyện thường; nhưng `launch` cũng có con (M1 Task 17 đã sửa để launch/async chờ con của chính nó), nên quy tắc theo-builder sẽ vẽ sai. Theo-số-con thì luôn đúng.

```ts
import { LexError } from './lexer/lexer'
import { ParseError } from './parser/parser'

/**
 * Bọc `runSource` để KHÔNG BAO GIỜ ném. Editor sống gọi hàm này ở mỗi nhịp
 * gõ phím, mà source lúc đang gõ thì gần như luôn dở dang: `runSource` ném
 * ParseError/LexError ở phần lớn các trạng thái trung gian đó.
 *
 * `runSource` vẫn giữ nguyên hành vi ném — golden test của M1 dựa vào nó, và
 * ở trong test thì ném là đúng: hỏng thì phải ồn ào.
 */
export function runSourceSafe(src: string): RunResult {
  try {
    return runSource(src)
  } catch (err) {
    return { diagnostics: [toDiagnostic(err)], events: [], output: [] }
  }
}

function toDiagnostic(err: unknown): Diagnostic {
  if (err instanceof ParseError || err instanceof LexError) {
    return { severity: 'error', message: err.message, line: err.pos.line, col: err.pos.col }
  }
  // Lưới an toàn cuối. Nếu tới được đây thì engine có lỗi thật, nhưng UI vẫn
  // phải sống để user còn sửa được code. Ghi rõ là bất thường.
  return {
    severity: 'error',
    message: `Lỗi không mong đợi trong engine: ${err instanceof Error ? err.message : String(err)}`,
    line: 1, col: 1,
    hint: 'Đây có thể là lỗi của công cụ, không phải của code bạn viết.',
  }
}
```

```ts
import type { Event, JobId } from './events'

export interface GraphNodeSpec {
  id: JobId
  parentId: JobId | null
  builder: string
  /** Container ⟺ có ≥1 con. KHÔNG suy theo builder: launch/async cũng có con. */
  isContainer: boolean
  isSupervisor: boolean
  name: string | null
  dispatcher: string
  /** seq của COROUTINE_CREATED. UI dùng để biết node đã "sinh ra" ở step nào. */
  bornAt: number
}

export interface GraphEdgeSpec {
  id: string
  source: JobId
  target: JobId
  kind: 'child' | 'failure' | 'cancel'
  /** Chỉ có nghĩa với kind 'failure'. */
  blocked: boolean
  /** seq của event đầu tiên tạo ra cạnh này. */
  firstSeq: number
}

export interface GraphSpec {
  nodes: GraphNodeSpec[]
  edges: GraphEdgeSpec[]
}

/**
 * Bộ xương graph, suy từ TOÀN BỘ trace — cố ý không nhận `upTo`.
 *
 * Vì sao không dựng graph từ `foldTrace(events, n)`: tập job lớn dần theo step,
 * nên ELK sẽ nhận đồ thị khác nhau ở mỗi step và trả toạ độ khác nhau. Mọi node
 * đã có sẽ nhảy chỗ mỗi khi một node mới sinh ra — không tua được.
 *
 * Tách hình dạng (hàm này, bất biến) khỏi trạng thái (`foldTrace`, theo step).
 * ELK chạy một lần cho mỗi lần compile; tua chỉ đổi diện mạo, không đổi vị trí.
 *
 * An toàn vì `foldTrace` chỉ THÊM job, không bao giờ xoá — tập node đơn điệu
 * tăng, nên tập đầy đủ là hợp của mọi tập trung gian.
 */
export function buildGraphSpec(events: readonly Event[]): GraphSpec {
  const nodes: GraphNodeSpec[] = []
  const byId = new Map<JobId, GraphNodeSpec>()
  const edges: GraphEdgeSpec[] = []
  const edgeSeen = new Set<string>()

  const addEdge = (
    source: JobId, target: JobId, kind: GraphEdgeSpec['kind'], blocked: boolean, firstSeq: number,
  ): void => {
    const id = `${kind}:${source}->${target}`
    // Gộp lần lặp lại: cùng một cặp có thể phát nhiều lần trong trace (vd
    // cancel lan xuống rồi lan lại). Cạnh là quan hệ, không phải lần xuất hiện.
    if (edgeSeen.has(id)) return
    edgeSeen.add(id)
    edges.push({ id, source, target, kind, blocked, firstSeq })
  }

  for (const e of events) {
    switch (e.k) {
      case 'COROUTINE_CREATED': {
        const n: GraphNodeSpec = {
          id: e.id, parentId: e.parentId, builder: e.builder, isContainer: false,
          isSupervisor: e.ctx.isSupervisor, name: e.ctx.name,
          dispatcher: e.ctx.dispatcher, bornAt: e.seq,
        }
        // Thứ tự chèn = thứ tự COROUTINE_CREATED = cha luôn trước con, vì con
        // không thể được tạo trước khi cha tồn tại. React Flow đòi đúng thế.
        nodes.push(n)
        byId.set(e.id, n)
        const parent = e.parentId === null ? undefined : byId.get(e.parentId)
        if (parent) {
          parent.isContainer = true
          addEdge(parent.id, e.id, 'child', false, e.seq)
        }
        break
      }
      case 'FAILURE_PROPAGATED':
        // Có thể trỏ vào node ĐÃ Cancelled (tồn đọng M1). Vẫn vẽ: nó mô tả
        // quan hệ với-tới-được theo cấu trúc, không phải trạng thái sống.
        addEdge(e.from, e.to, 'failure', e.blockedBySupervisor, e.seq)
        break
      case 'CANCEL_REQUESTED':
        if (e.from !== 'user') addEdge(e.from, e.to, 'cancel', false, e.seq)
        break
      default:
        break
    }
  }

  return { nodes, edges }
}
```

```ts
/**
 * Memo một-ô, so sánh tham chiếu theo từng đối số.
 *
 * Không phải để làm foldTrace nhanh hơn — đã đo, gập cả trace 16k event tốn
 * 0.49ms, tức 3% một khung hình 60fps. Lý do thật là ỔN ĐỊNH THAM CHIẾU:
 * foldTrace trả object MỚI mỗi lần gọi, nên gọi thẳng trong selector sẽ khiến
 * mọi component re-render ở mọi lần store đổi, kể cả khi stepIndex không đổi.
 */
export function memoizeTwo<A, B, R>(fn: (a: A, b: B) => R): (a: A, b: B) => R {
  let lastA: A | undefined
  let lastB: B | undefined
  let last: R | undefined
  let has = false
  return (a, b) => {
    if (has && lastA === a && lastB === b) return last as R
    lastA = a; lastB = b; last = fn(a, b); has = true
    return last
  }
}
```

```ts
import { create } from 'zustand'
import { compile, EMPTY_COMPILED, type Compiled } from './compile'
import { lessonSource, LESSON_LIST } from '../lessons/registry'

interface LabState {
  source: string
  compiled: Compiled
  stepIndex: number
  lessonId: string | null

  setSource: (src: string) => void
  setStep: (n: number) => void
  loadLesson: (id: string) => void
}

const clampStep = (n: number, len: number): number => Math.max(0, Math.min(n, len))

/**
 * Store giữ ĐÚNG BA thứ không suy ra được: source (user gõ), compiled (kết quả
 * của một hàm thuần trên source, ở đây vì compile theo debounce chứ không trong
 * render), stepIndex (con trỏ của user).
 *
 * KHÔNG được thêm WorldState, danh sách node, dòng console hay dòng highlight
 * vào đây. Chúng đều là hàm thuần của ba trường trên; giữ bản sao là dựng mô
 * hình state song song với trace — thứ chắc chắn trôi lệch khi tua ngược.
 */
export const useLabStore = create<LabState>((set, get) => ({
  source: '',
  compiled: EMPTY_COMPILED,
  stepIndex: 0,
  lessonId: null,

  setSource: src => {
    const compiled = compile(src)
    // Trace mới thì con trỏ cũ có thể trỏ ra ngoài. Kẹp thay vì về 0: khi user
    // sửa một dòng ở giữa, họ muốn ở lại gần chỗ đang xem.
    set({ source: src, compiled, stepIndex: clampStep(get().stepIndex, compiled.events.length) })
  },

  setStep: n => set({ stepIndex: clampStep(n, get().compiled.events.length) }),

  loadLesson: id => {
    const src = lessonSource(id)
    if (src === null) return
    set({ source: src, compiled: compile(src), stepIndex: 0, lessonId: id })
  },
}))

export { LESSON_LIST }
```

```tsx
import { useEffect, useRef } from 'react'
import { EditorState, type Extension } from '@codemirror/state'
import { EditorView, keymap, lineNumbers, highlightActiveLine } from '@codemirror/view'
import { defaultKeymap, history, historyKeymap } from '@codemirror/commands'
import { kotlinExtensions } from './kotlinLang'

export function CodeEditor({ value, onChange, extraExtensions = [] }: {
  value: string
  onChange: (src: string) => void
  extraExtensions?: Extension[]
}) {
  const host = useRef<HTMLDivElement>(null)
  const view = useRef<EditorView | null>(null)
  const onChangeRef = useRef(onChange)
  onChangeRef.current = onChange

  useEffect(() => {
    if (!host.current) return
    const v = new EditorView({
      parent: host.current,
      state: EditorState.create({
        doc: value,
        extensions: [
          lineNumbers(), history(), highlightActiveLine(),
          keymap.of([...defaultKeymap, ...historyKeymap]),
          ...kotlinExtensions,
          ...extraExtensions,
          // Gọi qua ref: nếu đưa `onChange` vào deps thì mỗi lần cha render lại
          // sẽ dựng lại cả EditorView, làm mất con trỏ và undo history.
          EditorView.updateListener.of(u => {
            if (u.docChanged) onChangeRef.current(u.state.doc.toString())
          }),
        ],
      }),
    })
    view.current = v
    return () => { v.destroy(); view.current = null }
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [])

  // Đồng bộ một chiều từ ngoài vào (loadLesson). So sánh trước khi dispatch,
  // nếu không sẽ thành vòng lặp vô hạn với updateListener ở trên.
  useEffect(() => {
    const v = view.current
    if (!v || v.state.doc.toString() === value) return
    v.dispatch({ changes: { from: 0, to: v.state.doc.length, insert: value } })
  }, [value])

  return <div className="editor" ref={host} data-testid="code-editor" />
}
```

- [ ] **Step 2: `elkLayout.ts`**

```ts
import ELK, { type ElkNode } from 'elkjs/lib/elk.bundled.js'
import type { GraphSpec } from '../../engine/trace/graph'
import { NODE_W, NODE_H, CONTAINER_PADDING } from './dimensions'

export interface Box { x: number; y: number; width: number; height: number }
export type LayoutResult = ReadonlyMap<string, Box>

const elk = new ELK()

const OPTS = {
  'elk.algorithm': 'layered',
  'elk.direction': 'DOWN',
  'elk.layered.spacing.nodeNodeBetweenLayers': '48',
  'elk.spacing.nodeNode': '32',
  // Bố cục con NẰM TRONG cha (compound thật sự), không đặt cạnh nhau.
  'elk.hierarchyHandling': 'INCLUDE_CHILDREN',
  'elk.padding': `[top=${CONTAINER_PADDING.top},left=${CONTAINER_PADDING.left},` +
                 `bottom=${CONTAINER_PADDING.bottom},right=${CONTAINER_PADDING.right}]`,
}

/**
 * Chạy ĐÚNG MỘT LẦN cho mỗi lần compile, không phải một lần mỗi step. Kéo
 * scrubber không bao giờ chạm tới hàm này (xem Task 15).
 *
 * Cạnh 'child' KHÔNG đưa vào ELK dưới dạng edge — quan hệ cha-con đã nằm ở
 * cây `children`. Đưa vào nữa thì ELK vẽ thêm một mũi tên từ hộp cha tới node
 * nằm bên trong chính nó.
 */
export async function layoutGraph(spec: GraphSpec): Promise<LayoutResult> {
  if (spec.nodes.length === 0) return new Map()

  const kids = new Map<string | null, typeof spec.nodes>()
  for (const n of spec.nodes) {
    const k = kids.get(n.parentId) ?? []
    k.push(n)
    kids.set(n.parentId, k)
  }

  const build = (parentId: string | null): ElkNode[] =>
    (kids.get(parentId) ?? []).map(n => {
      const children = build(n.id)
      return children.length > 0
        ? { id: n.id, children, layoutOptions: OPTS }
        : { id: n.id, width: NODE_W, height: NODE_H }
    })

  const root: ElkNode = {
    id: 'root',
    layoutOptions: OPTS,
    children: build(null),
    edges: spec.edges
      .filter(e => e.kind !== 'child')
      .map(e => ({ id: e.id, sources: [e.source], targets: [e.target] })),
  }

  const out = await elk.layout(root)
  const boxes = new Map<string, Box>()
  const walk = (n: ElkNode): void => {
    if (n.id !== 'root') {
      boxes.set(n.id, {
        x: n.x ?? 0, y: n.y ?? 0,
        width: n.width ?? NODE_W, height: n.height ?? NODE_H,
      })
    }
    for (const c of n.children ?? []) walk(c)
  }
  walk(out)
  return boxes
}
```

```ts
      const p = await prep(id)
      for (let n = 0; n <= p.events.length; n++) {
        expect(() => toReactFlow(p.spec, p.layout, foldTrace(p.events, n))).not.toThrow()
      }
    }
  })
})
```
